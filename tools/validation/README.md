# Runtime validation

Runs the Shield Expanded 1.7 port inside RimWorld and records pass or fail results. Decision: `docs/adr/0009-validation-runner-in-this-repo.md`.

## Game

- Install: `C:\SteamLibrary\steamapps\common\RimWorld`.
- Build: the target is the installed build, 1.7.5000 rev1275 (Steam unstable). ADR 0002 records this choice, updated on 2026-11-07. Every run before `20261105-233814` used 1.7.4998 rev1299, the build installed then.

## Rules

- Each gameplay change runs red before its fix and green after it. The run fails on the bug and passes on the fix.
- Every run uses its own save folder under `.artifacts/runs/<timestamp>/`, passed with `-savedatafolder`. Never write to the live save folder or the live `ModsConfig.xml`.
- Refuse to start while `RimWorld.exe` is running. The scenario runner also stops a run when another RimWorld process starts during it.
- One RimWorld session at a time. Every session writes its log to the same `AppData\LocalLow\Ludeon Studios\RimWorld by Ludeon Studios\Logs\Player.log`, and `-logFile` does not move that log in this build. Two sessions mix their lines, so the log copy proves nothing about either run. The ZLevels runner in `rimworld-modding` writes to the same log.
- The port's mod folder reaches the game through a junction under `<RimWorld>\Mods\`. Create the junction for the run, and remove it after the run.
- A run passes only when every required scenario row reads PASS, every group completion row reads finished, every result row is named in `$required` or `$groups`, the log has one `[ShieldValidation]` marker for each row, and the log has no error line that mentions the port or the test mod. A row that neither list names fails the run, even when it reads PASS. The runner compares the marker count with the row count. It does not compare the text of each marker.
- Never commit `.artifacts/`.
- Each scenario group writes one `<group> group complete` row when it ends. To add a group, list its completion row in `$groups` and its scenario rows in `$required`, both in `Invoke-Scenarios.ps1`. A row that the lists do not name fails the run, so list each new row when you add its check.
- Game time: the game ignores a speed change made while the player has no control. A new colony's first tick is still fading, so the groups' speed setter does nothing, and the speed stays Normal. The mech serum group advances the game with the game's own per-tick function, because a finger takes 28,833 ticks to regrow. The other groups run in real time. Lucas chose to keep this loop on 2026-11-07, as decision D3 and ADR 0009 record. See `docs/game-api-findings.md`.

## Recordings

- `Record-CombatDemo.ps1 -Scene turret` is the default. It records the real game window in a new colony. A shield generator's dome stops a hostile turret's shots, and one drafted colonist stands inside the dome. It runs `ShieldValidation\CombatDemo.cs` with `-shieldvalidation-combat`.
- `Record-CombatDemo.ps1 -Scene raid` records a raid in the same kind of colony. Three colonists stand inside the dome, each with a rifle and an ES0 belt. Three raiders with revolvers stand outside it. It runs `ShieldValidation\RaidDemo.cs` with `-shieldvalidation-raid`. By default the raiders run the game's own raid lord (`-RaidAI game`). `-RaidAI scripted` gives them the scripted aim instead.
- Both scenes write only `[ShieldCombat]` lines and no validation rows, so the runner's rules do not change. The shared dome, power row, and frame capture are in `ShieldValidation\DemoScene.cs`. Output goes to `.artifacts\combat\<timestamp>\`: `combat.mp4`, `summary.txt`, `Player.log`, and the frames.
- The turret scene is scripted. Other colonists are despawned, the colonist is drafted and unarmed, and the turret is placed when the dome comes up. In the raid scene, colonists past three are despawned, and the colonists are drafted and armed. Raiders are placed when the dome comes up. With `-RaidAI scripted`, each raider holds its spawn spot on the game's defend duty and is given an attack-from-here job on the nearest colonist it can hit. The bare assault and defend duties left the raiders with no target in test runs `20261108-110251` and `20261108-110839`. Both scenes start the generator's battery with 300 Wd, and the buildings belong to the player. Every other setting is the game's default.
- Run `20261108-010345` is the turret scene on 1.7.5000 rev1275. It shows 22 shots fired, 22 intercepted, 0 colonist injuries, and the dome up at the end. Run `20261108-112114` is the turret scene after the refactor, and it gives the same result.
- Run `20261108-111632` is the raid with the scripted aim. It shows 128 raider shots fired and 41 intercepted. Colonists fired 47 shots, and none ended at the dome edge. The dome went down three times. The belts absorbed 18 hits. Thirteen colonist injuries came after the belts broke, and two colonists ended the fight downed. One raider died. The fight ended at the 90-second limit with the dome up. The one ERROR line is the duplicate packageId `Aoba.DeadManSwitch.Core`, the same as the smoke run.
- Run `20261108-114853` is the raid with the game's own raid lord, which is the default now. It shows 140 raider shots fired and 46 intercepted. Colonists fired 56 shots, and none ended at the dome edge. Four raider health losses happened 18 to 24 cells from the generator while the dome was up. The colonists took no injuries, and the belts absorbed 25 hits. The dome went down four times, and the fight ended at the 90-second limit with the dome down.

## Known issues

- The 1.6 build has no runtime runner. Lucas chose on 2026-11-08 to fix the usability check in both builds (decision D4, ADR 0011). He then allowed a 1.6 rebuild in `AGENTS.md` (decision D7). The 1.6 assemblies were rebuilt from the fixed source. A decompile diff against the old assemblies shows the usability fix as the only change that runs in 1.6. The Fast regen code is compiled into 1.6 too, but nothing in 1.6 raises the regen severity above 0.5, so that code does not run there.
- The Fast rows call the injector's `DoEffect` method directly. The usability row calls `CanBeUsedBy` directly. No row runs the game's use job from start to end, so the path a player takes to use an injector is not covered.
- The Fast label reads `Fast Regen` on a healthy Fast pawn, although its regrowth runs at the normal speed until a bleed starts. The wording is not decided.
- `RimElShrine.Shields/About/PublishedFileId.txt` was removed in `cf808da`, because it held the original mod's Workshop item id, 3575073524. After the first private upload, record the port's own id in that file.
